# Changelog

All notable changes to this package are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the package uses [Semantic Versioning](https://semver.org/). The first release will be `1.0.0-beta.1`; until then everything is listed under Unreleased.

## [Unreleased]

### Added

- `laravel-pitfalls` skill: pitfalls taken from real reviews (concurrency, transactions, idempotency, authorization, population, personal data in logs, edge validation, docs claims), each with its fix, its test and a note on what Boost already covers.
- PHPStan rules for those pitfalls, shipped as `extension.neon`.
- `laravel-package-verdicts` skill: a register of verdicts on common Laravel packages (use, avoid or depends), which a project profile can override.
- House PHP style guideline (strict types, PHPDocs on every class and method, `@author`, section headers), on by default and switched off with `"laravel": {"house_style": false}`.
- Project files guideline: README, docs, CHANGELOG and LICENSE ship where they apply and are updated in every slice that changes behavior, without waiting to be asked; it wins over Boost's "only create documentation files if explicitly requested".
- `claude-skills:setup` command for apps and Testbench packages: the runner (DDEV or host) for `.mcp.json` and the guidelines, an isolated test suite (forced PHPUnit pins, a `<slug>_test` database with a DDEV hook), the one gate command `composer test`, the commit-msg hook and secret scan, and `phpstan.neon` at the profile's level.
- The project profile `.ai/skills-profile.json`: runner, house style, PHPStan level, monitoring, the CI workflow, extra setup steps, package verdicts and outside builders. A value with a trailing newline is refused; `"laravel": []` counts as no options.
- `laravel.test_database: ddev`: a Testbench package on DDEV tests on DDEV's db service, as an app does (hook, credentials, pins and a CI database service on the same engine and version). With no `database:` block in `.ddev/config.yaml`, or one without a version, the engine and version come from the installed DDEV (`ddev describe -j`, `DDEV_DATABASE`, or the default `ddev config --help` prints); when DDEV cannot tell, the setup asks for an explicit block. DB keys you set in your own DDEV `web_environment` are left to you.
- `laravel.test_pins`: override single PHPUnit pins (`SESSION_DRIVER`, `CACHE_STORE`, `QUEUE_CONNECTION`, `MAIL_MAILER`) with a value or `env`; isolation stays the default.
- `laravel.php_matrix`: the CI workflow tests a list of PHP versions; a package defaults to every minor from its `require.php` floor to the latest.
- The setup creates an empty `CLAUDE.md` before Boost runs (so Boost never writes `AGENTS.md` instead) and, for a Pest package whose tests pick no base case yet, `tests/Pest.php`; it never touches either once it exists, and refuses a symlinked `tests` folder or a `CLAUDE.md` that links outside the project.
- Agents as a Claude Code plugin: planner, gate writer, builder, review checker, reviewer, deep reviewer and debugger, with locked gate tests, lock checks, revert-to-prove and an independent checker.
- `scripts/check.sh`: the package's deterministic quality gate.
- The setup lists every effective option with its source (`profile` or `default`) on every run, prints the two commands that install the agents plugin until it is enabled, and ends a plan with `<N> changes planned.`
- A package's `phpstan.neon` checks the existing `src`, `tests` and `workbench/app` directories, so a fresh package passes its own gate.
- The gate writer formats its own test files before the gate commit and reports every public name it chose under Open; the builder lists its steps without a todo tool, pushes and opens a PR only when the brief asks, stops a tripwire check after one test row per bypass, updates the README and CHANGELOG for its slice, and a gated PR merges with a merge commit, never a squash.
- The README documents the install order per project kind, requiring the unreleased pack from GitHub, the non-interactive Boost recipe and `boost:update` after a DDEV PHP change.
- Agents: a defect an agent finds is fixed in the slice or raised with the owner, never deferred, and every hand-back or report carries a `Learnings:` line (gaps in the agent or skill rules, stack learnings with evidence, or none). The gate writer works only from the pasted brief, stops on unstated values, and hands back `Values chosen:`, `Green by design:`, `Passability:`, `Constraints:`, `Breaks later:` and `Suite:`; the builder uses general-purpose stand-ins for a missing checker or gate writer type, reads vendor source when Boost's tools are missing, commits without attribution, watches CI after a push and proves new files and several fixes per file by mutation; the reviewers quote `|` filters, treat any vendor package source as evidence, check auth flows and give a `Merge:` result line, blocked on any Critical or Important finding or an unmet MUST; the planner fixes each slice's public names. A README describes behavior and never cites tests; docblocks and code comments name the test that proves a claim.
- On DDEV the setup writes `.ddev/web-build/Dockerfile.gitleaks`, which installs the gitleaks release the CI workflow pins (checksum verified per architecture) into the web image, so the local secret scan equals CI's; inside DDEV a missing gitleaks now fails the scan and names `ddev restart`. docs/profile.md explains the scan's scope (local history, one commit in CI) and `.gitleaksignore` by fingerprint for a historical false positive.
- The setup creates `boost.json` (Claude Code, this pack, the Laravel Cloud skill off) when it is missing, for a non-interactive `boost:install`; an existing one is never changed.
- Every run prints suggested `.claude/settings.json` content (one exact rule for the gate command, no wildcard, and the agents plugin); the setup never writes `.claude/settings.json`.
- The PHPUnit pins force `BCRYPT_ROUNDS=4`, as Laravel's app skeleton does; a `BCRYPT_ROUNDS` the file sets without force is left alone.
- The CI database service of an app on DDEV whose `.ddev/config.yaml` names no database (or no version) follows the installed DDEV instead of assuming MariaDB 10.11; when DDEV cannot tell, the setup warns and uses DDEV's documented default, MariaDB 11.8.
- `laravel.ci_services`: `["redis"]` adds a Redis service and `REDIS_HOST` and `REDIS_PORT` to the CI workflow's gate job, beside the database; any other name is refused.
- `laravel-pitfalls`: new references for single use, counters and throttles on cache stores (atomic `add` by driver, failover stores, eviction, write-once keys, RateLimiter under concurrency, the burn-then-insert deadlock), sign-in and sessions (remember me and `Login`, `password.confirm`, revoking one device, opt-in middleware, lookups by address under a collation, secrets derived from `APP_KEY`, laravel/passkeys), queued payloads (users, secrets and locales in the queue), environments (DDEV and CI engines, DDL and connections on MySQL, Redis on DDEV's shared network) and package authoring (dependencies, providers, tagged services, framework internals, Testbench scripts, pruning); edge validation adds booleans passing an integer check, the trailing-newline regex, raw string ids and a portable LIKE alternative; PII in logs adds content tripwires.
- Testing notes (`laravel-pitfalls`, testing): tests named by feature with R and AC ids in Pest groups, Testbench suites, parallel-process gates, several devices in one test, time travel with file sessions, `queue:work` in the suite and rendering a Boost guideline.
- Verdicts for `laravel/passkeys` (depends, pre-1.0), `orchestra/testbench`, `spatie/laravel-package-tools` and `spatie/guidelines-skills`, and a note on `illuminate/*` against `laravel/framework` in a package's `require`.
- House style: never mix single-line and multi-line chaining; events named by tense and listeners by their action.
- Agents: gate files named by feature with ids in groups and gates run as `--group=`; the gate writer races every write path, interleaves single-use gates, checks Redis on DDEV before using it and orders new-content assertions first; the builder reports Artisan command progress, looks for a second guard when a mutation stays green and describes its mutate script; the planner pairs a development service with a slice that installs it; the reviewer requires an authorization test for every restricted route; the security lenses check lookups by address and trace opt-in middleware across an uncovered route; the deep reviewer accepts a constant `SELECT` and the database manual as evidence and reports untested MUSTs.
- New setup warnings: Boost output under the Testbench skeleton in `vendor/`, a `CLAUDE.md` that names another PHP version than DDEV (with the runner's `boost:update`), a hand-edited setup `phpstan.neon` that shadows `phpstan.neon.dist`, an existing package suite moving to `test_database: ddev` (with the base TestCase in docs/profile.md), and project workflows that run the tests without a database service.
- The package runner guideline says where package classes go (`src/` and the composer namespace), that `make:` generators write into the skeleton, and to run tests with `vendor/bin/pest`; the README explains `boost.enforce_tests` for a package.
- README: installing the skills through skills.sh (`npx skills add michtio/laravel-claude-skills`), and using the pack next to spatie/guidelines-skills with `"house_style": false`.
- Outside builders: the `laravel-gated-build` skill runs a gated slice through the builders the profile names, in order, called as `<command> <brief-file> <handback-file>` (exit 0 done, 3 unavailable, any other exit or a passed `timeout_minutes` failed), resets the tree before each one, checks each result with both lock checks, the hand-back checker, a gate rerun and `laravel-review-checker`, and falls back to `laravel-builder` from the same brief. It prints the builder commands and runs none without your yes to that list. `docs/brief-format.md` and `docs/outside-builders.md` define the brief, the hand-back and the protocol for any builder; `scripts/builders_check.py` skips builders with an unsafe name (anything outside `^[A-Za-z0-9._-]{1,64}$`), a command holding a Unicode control, format or separator character (a newline, a right-to-left override, a zero-width space) or a bad timeout, and writes the checked list that `scripts/run_builder.py --builders <file> --name <name>` runs with its timeout, so no profile value is quoted into a shell line; `scripts/suite_guard.py` disqualifies a builder that changes the files deciding test isolation (`phpunit.xml`, `phpunit.xml.dist`, `tests/Pest.php`, `tests/TestCase.php`, `.env`, `.env.testing`, `testbench.yaml`, `config/database.php` and the phpunit bootstrap file (unless it is under `vendor/`), snapshotted after the gate commit) or, on a suite that is not isolated, adds a database-wiping test, before the gate is rerun on its code; `scripts/handback_check.py` checks a hand-back's required lines and refuses a brief with no usable `Gate commit:`. The profile's `builders` example no longer shows a `{brief}` placeholder.
- Outside builders are confirmed once per machine: after your yes, `scripts/builder_trust.py add` keeps each confirmed builder in a trust file outside the repository (`~/.config/laravel-claude-skills/trusted-builders.json`, moved by `XDG_CONFIG_HOME` or `LARAVEL_CLAUDE_SKILLS_TRUST_FILE`, mode 0600), keyed on the repository's git top-level and origin URL and the builder's exact name, command and timeout. `builder_trust.py check` marks trusted builders `(trusted)` and writes the list the gated build runs from, so a trusted builder runs without asking, unattended runs included; any change asks again, and a trust file inside the project, writable by others, owned by another user or corrupt is ignored. `builder_trust.py list` and `remove --root <project root> --name <name>` show and revoke entries. A command that runs a repository file is also keyed on that file's sha256, a task runner (`make`, `composer`, `npm` and the like) is marked `(runs repo code)`, and the origin URL is stored without its user, password or token. Commands are resolved as the shell runs them (leading `VAR=value`, the wrappers `env`, `nice`, `timeout`, `nohup`, `exec` and `command`, PATH lookup), a command after a wrapper that cannot be found is never trusted, and `php artisan` and `python -m` count as task runners. The origin also loses its query and fragment. The trust file is refused inside any git work tree or when it is not a regular file, is read through one descriptor, and is fsynced on write; `add` and `remove` hold a lock while they write, and `add` runs only on a yes in your own message (never allowlist it).
- `scripts/suite_guard.py wipers` also finds tests that call `migrate:fresh`, `migrate:refresh`, `migrate:reset` or `db:wipe` through `$this->artisan(...)`, `artisan(...)` or `Artisan::call(...)`; `migrate` and `migrate:status` are not flagged.
- The setup refuses an unsafe outside-builder name: a `builders` entry whose `name` is not 1 to 64 letters, digits, dots, underscores or hyphens (`^[A-Za-z0-9._-]{1,64}$`, a trailing newline included) makes the profile invalid (`Invalid profile .ai/skills-profile.json: builders.<i>.name: ...`, exit 1, nothing written). The profile schema carries the same pattern.
- The builder has a consolidation mode (no behavior change, `tests/` unchanged against the base commit) with `Duplicates merged:`, `Dead code removed:`, `Files split:` and `Tests unchanged:` hand-back lines; after a setup change that pins a real test database it checks every CI workflow can reach it before the first push. The gate writer shows the next layer with a reverted stub when one shared fixture fails every test first.
- The pack's own CI runs an unused-public-code check (shipmonk/dead-code-detector, through `phpstan-dead-code.neon`), with a verdict row in the register.

### Changed

- The DDEV tinker form passes its code raw (`ddev exec --raw -- php ... tinker --execute '...'`), in the runner guideline and the derived core override, so a `$` in the code is no longer expanded by the container shell; the guideline points to Boost's `tinker` MCP tool first. `ddev artisan` stays as it is.
- `testbench.yaml` is edited as text: comments, blank lines and the commented `providers:` item stay, and `providers: null` is no longer written.
- `--check` exits 0 after taking PHPStan over (`phpstan.neon.dist` created, the setup's `phpstan.neon` deleted); the stale record stays until the next real change.
- The plan's `N changes planned.` and the apply's `Applied: N changes.` count the same changes: the state file counts only when it is the one change.
- The pitfall references no longer cite the pack's own test files: shipped skill references are user-facing.
- The setup's extra steps refuse every Unicode control, format, surrogate, private-use or unassigned character and every line or paragraph separator in a step name or command (a right-to-left override, a zero-width space), as `builders_check.py` does for builder commands, not only C0 and C1 controls; a command still keeps its tabs and newlines.
